# Leela UX Continuous Improvement Plan v15

> Generated by autonomous loop on 2026-08-08 (cycle 11). Focus: backend ingestion of cancellation survey responses + lightweight dev analytics surface.
> Continues from `UX_IMPROVEMENT_PLAN_V14.md`.

## Executive Summary

Cycle 10 shipped a cancellation survey + save offer flow that persists responses locally in AsyncStorage. Cycle 11 makes that data actionable by uploading responses to Firestore and surfacing them in a lightweight developer/PM view. This closes the feedback loop so the team can see churn reasons and offer acceptance rates without waiting for manual export.

**New critical findings:**
1. **Local responses are invisible to the product team** — AsyncStorage data is stuck on the device.
2. **No deduplication** — re-uploading the same responses would inflate churn metrics.
3. **No retry on upload failure** — offline users lose their responses forever if a single upload fails.
4. **No dev/PM surface** — there is no screen to inspect experiment status and cancellation survey trends.

## Competitor UX Benchmark (cycle 11)

| Source | Pattern to borrow |
|---|---|
| [Datafly Signal offline & batching](https://docs.dataflysignal.com/mobile-sdks/offline) | Persist locally, batch upload, exponential backoff, drop oldest on overflow |
| [Sankofa ingestion model](https://docs.sankofa.dev/concepts/ingestion-model/) | Client-side `event_id` deduplication, at-least-once delivery |
| [Segment RetryManager state machine](https://github.com/segmentio/analytics-react-native/commit/1f56a4dac6035045f358ccd9ebd5ab58a759f53f) | Exponential backoff + jitter, retry state survives restarts |
| [Amplitude RN offline mode](https://www.docs.developers.amplitude.com/data/sdks/typescript-react-native/) | Native connectivity detection, flush on reconnect |
| [Mixpanel RN flush](https://github.com/mixpanel/mixpanel-react-native/) | Periodic flush + manual flush, native-managed retry |

**Key patterns to adopt this cycle:**
- Upload cancellation responses to Firestore under a per-user `ChurnSurveys` collection.
- Generate a stable `responseId` from `submittedAt` for deduplication.
- Mark locally-stored responses as synced after a successful write.
- Retry upload failures silently (1 immediate + 1 delayed retry) without blocking the user.
- Add a developer-only `DiagnosticsScreen` that shows:
  - Latest cancellation responses (local + sync status).
  - `gameTodaySummary` experiment recommendation.
  - Quick actions: force flush, clear local queue.
