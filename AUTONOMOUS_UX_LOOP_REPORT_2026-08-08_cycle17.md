## 1. Research findings

### Weak spots in the current flow
- `INPUT_TEXT_MODAL` closed immediately after the caller's `onSubmit` resolved; if `onSubmit` threw, the modal was gone and the typed text was lost.
- `DetailPostScreen` added an optimistic comment, then **removed** it and showed a generic `Alert.alert` on failure, which also discarded the user's text.
- `CommentCard` and `SubCommentCard` reply/edit actions returned promises but errors were swallowed inside the modal because it used `return` after the catch instead of keeping the modal open.
- `SubCommentCard` had no visible reply affordance — users had to open the overflow menu to reply to a thread.

### Competitors / patterns consulted
- UX Patterns Guide: comments should preserve draft state across transient failures and offer inline retry.
- UX Patterns Guide — Error state: keep failure visible near the affected content, do not navigate away from the user's context.
- OpenChamber real-world fix: snapshot submission before clearing input and restore on hard errors.
- PostHog pattern: surfaced reply as an always-visible icon instead of hiding it in overflow.

## 2. Implementation summary

### 2.1 `src/screens/Modals/InputTextModal/index.tsx`
- Added `submitting` and `submitError` states.
- `handleSubmit` now waits for `onSubmit` to resolve before navigating back.
- On error: the modal stays open, the typed text is preserved, and an inline error row with a **Retry** button appears.
- Added a visible **Send** icon (Ionicons paper-plane) while idle, replaced with a "sending…" label during submission.
- Input is disabled while `submitting` to prevent double-posts.

### 2.2 `src/screens/DetailPostScreen/index.tsx`
- Removed the optimistic comment + alert-on-failure pattern.
- The caller now simply throws on missing auth and lets `PostStore.createComment` throw on Firestore failure.
- Removed unused imports (`nanoid`, `Alert`, `CommentT`, `OnlinePlayer` usage inside the callback).

### 2.3 `src/components/Cards/CommentCard/ModalActions.ts` and `SubCommentCard/ModalActions.ts`
- All `onSubmit` callbacks are now `async` and let errors propagate to the modal.

### 2.4 `src/components/Cards/SubCommentCard/index.tsx`
- Added a visible reply button next to `Reactions`.
- The button opens `INPUT_TEXT_MODAL` with the same threaded-reply payload used by the overflow menu.

### 2.5 Localization
- Added `inputTextModal.send`, `inputTextModal.retry`, and `inputTextModal.sending` to all 10 locale files.
- Translated the RU keys (`Отправить`, `Повторить`, `отправка…`).

### 2.6 Tests
- Added `src/screens/Modals/InputTextModal/index.test.tsx`:
  - renders input and send button;
  - submits typed text and navigates back on success;
  - keeps modal open, shows retry, and preserves draft text on failure;
  - retries successfully and then closes;
  - disables input while submitting.
- Mocks added for `@react-navigation/elements` and `react-native-safe-area-context`.
