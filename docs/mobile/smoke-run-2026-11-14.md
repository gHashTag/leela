## Reproducible paywall runbook (from code, 2026-11-15)

**Two and only two entries into SUBSCRIPTION_SCREEN exist:**

1. **Board WebView message** (offline path): the 3D board counts free moves; on the
   third it posts `{what:'subscribe'}` (`leela:subscribe:v1`, limit `se=3` in
   `ios/board/assets/index-*.js`), and `BoardScreen` navigates to SUBSCRIPTION_SCREEN
   (`BoardScreen/index.tsx:283`). Requires a *live* game: intention entered + a six
   thrown + pieces actually moving. The GameScreen paywall button does not count:
   `isBlockGame` is permanently `false` (`SubscribeStore.ts` — "There is no paywall
   now"), that button never renders.
2. **Settings row** (online path): `ProfileScreen → ⚙ Settings → ⭐ Subscription`
   (`settings-subscription`, `SettingsScene/index.tsx:202`). Requires an online
   Firebase account.

**Dice ↔ DiceStore sync (order item 5, answered from code):** `BoardScreen` handles
exactly two postMessage types — `subscribe` and `ask` (the AI question). There is no
dice-state sync message. The WebView board keeps its own die state; the native
`DiceStore` drives the flat 2D `GameScreen` (`TAB_BOTTOM_3`) only. The two dice are
separate surfaces by design.

**Why the blind run stalled:** we were on `TAB_BOTTOM_0` (3D board) with no game
live. Rolls changed pixels (the die animates) but could not count as moves without
the intention step, which lives inside the WebGL layer and is not reachable via AX.

**Manual repro (owner, 2 minutes, offline):** Welcome → «offline» → select 1 player →
Start → on the 3D board enter the intention when asked → roll until a 6 → the pawn
enters → make 3 moves → the subscribe prompt/paywall appears → screenshot → cancel →
verify no alert and no Sentry. Then Settings/Profile checks only apply online.

**Online repro (needs a Firebase test account — owner decision):** sign in → tabs →
Profile → Settings → ⭐ Subscription → paywall opens regardless of game state.
