## 1. Research findings

### Weak spots in the current `ChatScreen` AI flow
- The only **Stop generating** affordance was an 18 pt icon embedded inside the loading bubble; it was easy to miss and disappeared if the user scrolled.
- After a successful assistant answer there was no way to ask Leela to **regenerate** it; the user had to retype the prompt.
- After a failed/cancelled turn there was no **Edit prompt** shortcut; recovery meant either retrying the exact same prompt or retyping it from scratch.
- The error bubble showed only a retry icon, with no affordance to tweak the question.
- The previous `handleRetry` implementation already reused `lastUserMessageRef` / `lastApiMessagesRef`, but there was no equivalent tracking for the last assistant message.

### Competitors / patterns consulted
- **ChatGPT / Claude mobile apps**: a persistent composer-level "Stop generating" bar, plus per-message "Regenerate" and "Edit prompt" actions.
- **Perplexity**: surfaces retry and edit affordances directly on the message that failed, reducing the distance between error and recovery.
- **Apple HIG**: AI features should always provide an escape hatch; the cancel control should live near the control that initiated the action (the composer / top bar).

## 2. Implementation summary

### 2.1 `src/screens/Tabs/ChatScreen/index.tsx`
- Added a controlled composer (`inputText` + `onInputTextChanged`) so "Edit prompt" can pre-fill the input.
- Added `lastAssistantMessageRef` to track the most recent assistant content message.
- Added a top `StreamStatusBar` (rendered while `loading`) with an activity indicator, "Leela is thinking…" label, and a large **Stop generating** button.
- Removed the duplicated tiny stop icon from the loading bubble; the stream bar is now the single, prominent cancel affordance.
- Added `handleRegenerate`: removes the last assistant message and re-runs the stream on the same user turn without creating a duplicate post.
- Added `handleEditLastPrompt`: pre-fills the composer with the last user message text and removes the failed/error assistant answer (if it is still the most recent message), turning recovery into a retry-with-edit.
- Updated `renderBubble` so the last assistant message shows **Regenerate** next to copy, and the last user message shows **Edit prompt**.
- Updated the error bubble to show both **Retry** and **Edit prompt** icons.
- Ensured unmount cleanup still aborts any active stream.

### 2.2 Localization
- Added `chat.generating`, `chat.regenerate`, and `chat.editPrompt` to all 10 locale files.
- Provided Russian (`Лила думает…`, `Сгенерировать заново`, `Изменить запрос`) and French translations; other locales fall back to English (matching the existing pattern for `chat.stop` / `chat.retry`).

### 2.3 Tests
- Created `src/screens/Tabs/ChatScreen/index.test.tsx` with a mocked `GiftedChat`:
  - stream status bar appears while generating;
  - stop button aborts the active stream;
  - retry and edit actions appear on a failed turn;
  - regenerate action appears on the last assistant message after success;
  - edit prompt pre-fills the composer with the last user message.
