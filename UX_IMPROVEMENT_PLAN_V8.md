# Leela UX Continuous Improvement Plan v8

> Generated by autonomous loop on 2026-08-07 (cycle 5). Focus: cross-platform toast abstraction + iOS 17+ privacy strings + community trust seed.
> Continues from `UX_IMPROVEMENT_PLAN_V7.md`.

## Executive Summary

After cycle 4 made the game screen A/B-ready with haptics and a first-roll helper, cycle 5 closes two long-standing gaps that block both iOS App Store review and a polished cross-platform UX: the app still uses `ToastAndroid` directly, and its `Info.plist` privacy strings are generic or empty.

**New critical findings:**
1. **`ToastAndroid` is used directly in two places** — `Dice` and `PlansDetailScreen`. On iOS the `if (ToastAndroid)` guard prevents a crash, but the user gets no feedback at all when an action is blocked.
2. **`Info.plist` privacy strings are review-rejection risks** — `NSLocationWhenInUseUsageDescription` is empty, `NSCameraUsageDescription` and `NSPhotoLibraryUsageDescription` are generic, and iOS 17+ requires specific, user-facing purpose strings for every referenced privacy API.
3. **No trust anchor for community data** — there is no in-app way for a user to request their data export, which is increasingly expected by App Store reviewers and GDPR/CCPA-conscious users.
4. **Dependency install for haptics is still pending** — `react-native-haptic-feedback` is in `package.json` but not yet installed/poded.

## Competitor UX Benchmark (cycle 5)

| Source | Pattern to borrow |
|---|---|
| [React Native `Alert` docs](https://reactnative.dev/docs/alert) | Use built-in cross-platform alerts for blocking errors; keep toasts for lightweight confirmations |
| [Burnt toast library](https://github.com/nandorojo/burnt) | Native cross-platform toast/alert with haptics and presets |
| [Apple QA1937 privacy purpose strings](https://developer.apple.com/library/archive/qa/qa1937/_index.html) | Every privacy API must have a specific, user-facing `NS*UsageDescription` in the base `Info.plist` |
| [OWASP MASVS-PRIVACY-4](https://mas.owasp.org/MASVS/controls/MASVS-PRIVACY-4/) | Provide in-app controls for users to manage/export/delete their data |
| [GDPR/CCPA data export best practices](https://guptadeepak.com/ciam-compass/best-practices/user-data-export/) | JSON/CSV export, identity verification, no email attachments, 30-day max fulfillment |

**Key patterns to adopt this cycle:**
- Cross-platform `notify()` utility that uses `ToastAndroid` on Android and `Alert` on iOS for now (Burnt can be adopted later without changing call sites).
- Specific, review-tested privacy purpose strings for camera, photo library, microphone, speech recognition, and location.
- A "Download my data" CTA in profile with a skeleton JSON export builder.
